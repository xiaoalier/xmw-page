状态 BFS：把「局面」当成点来搜

1状态 BFS 的思路

点不是坐标

有时候 BFS 的点是「一个局面」，比如三个杯子里的水量、某个开关组合。

边是操作

每次操作让局面变到另一个局面，就相当于走一条边。

求最少操作

从初始局面到目标局面，最少几步——就是最短路。

📌框架
queue<State> q;
dist[初始状态] = 0; q.push(初始状态);

while (!q.empty()) {
    State u = q.front(); q.pop();
    if (u == 目标) return dist[u];
    for (每种操作) {
        State v = 操作后的状态;
        if (没访问过) { dist[v] = dist[u] + 1; q.push(v); }
    }
}

⚠ 关键是把「状态」设计得能放进 dist 数组或 map 里（比如打包成一个整数）。

2状态怎么存

📌常见做法
① 一维：把局面映射成整数（如水量 x*100 + y）
② 字符串：把局面写成 "0123" 这类串，用 map<string,int> 记距离
③ 位运算：用二进制表示「选了哪些」（状压）

⚠ 状态数可能很多，先估一下「总状态数」会不会爆内存。

6小贴士

💡 小贴士

  • 状态 BFS 的「点」是局面，不是坐标。
  • 关键是把状态唯一地表示出来。
  • 状态数要估一下，别爆内存。
  • 求最少操作次数就用 BFS。
  • 框架和普通 BFS 完全一样。
